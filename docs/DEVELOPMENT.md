# Development

## Environment and commands

Follow [root setup](../README.md#development). [package.json](../package.json) owns Node/pnpm and dependency versions; [CI](../.github/workflows/ci.yml) selects its runtime. Tests need Node SQLite. Android builds/sync require Java 21: recheck Android Studio’s Gradle JDK after regeneration and set `toolchainVersion=21` in `android/gradle/gradle-daemon-jvm.properties` when present. Bundled Java 25 can fail Prefab through native-access warnings.

The [package manifest](../package.json) defines all scripts:

| Command | Purpose |
| --- | --- |
| `pnpm start` | Start Expo |
| `pnpm android` / `pnpm ios` | Build and install the native debug app and start Metro; these do not generate release builds |
| `pnpm build` | Export production Android and iOS JavaScript bundles |
| `pnpm typecheck` / `pnpm lint` / `pnpm deadcode` | Run individual static checks |
| `pnpm test:coverage` | Run tests with enforced coverage |

Use Android Studio/emulator for Android and Xcode on macOS for iOS (`a`/`i` in Expo). Fast Refresh handles source edits; `pnpm start --clear` clears stale Metro cache. `deadcode` runs Knip. Web is unsupported.

## Generated Android files and assets

`app.json`, manifest, and lockfile own native configuration. Ignored `android/` is generated by `pnpm android` when absent and retained locally for Android Studio/signing. Preserve local native changes and signing material before regeneration; durable configuration belongs in source.

After any Expo SDK change, regenerate with `pnpm expo prebuild --platform android --no-install`. Old templates can reference removed native APIs even when Doctor and JavaScript exports pass.

Android `app/build/`, `app/.cxx/`, `build/`, `.gradle/`, and `.kotlin/` are disposable caches/output; remove only with builds stopped. Rebuilding recreates them and takes longer. Retain signing files/release bundles through their release lifecycle.

`assets/app/icon.png` supplies launcher and attribution-free native splash artwork; `app.json` sets launch size. Credit PalFly in More → Help & about. Splash changes need native regeneration/rebuild; verify Android masking within the central safe area on device. [Startup](UI_UX.md#startup) owns splash timing.

## Android connection troubleshooting

Keep Metro running while using a debug build. If the app cannot load JavaScript:

1. Check Metro at `http://localhost:8081/status`.
2. Run `adb reverse tcp:8081 tcp:8081` for a connected Android device.
3. If needed, set **Change Bundle Location** in the developer menu to `localhost:8081`.

Repeat port forwarding after reconnecting. Release builds include their JavaScript bundle and do not need Metro.

## Android release builds

Every new Play bundle needs an `expo.android.versionCode` above all uploaded codes, independently of visible app version. Release preparation increments it; align with the highest uploaded code.

### GitHub release sequence

1. On `main`, manually run **Prepare release**, choosing `patch`/`minor`/`major` and **Android**. Enter plain-text English/Spanish notes without language tags, at most 500 characters each. Blank inputs use “General updates and improvements.” / “Actualizaciones y mejoras generales.”
2. Preparation pushes a release branch, creates its PR into `main`, and dispatches **CI**. Review notes from the workflow summary, wait for latest-commit checks, and merge manually; no auto-approval/merge. CI rejects incomplete, TODO, or oversized notes. If dispatch fails, run CI on that branch; approve approval-required workflows. If PR creation fails, enable the Actions setting below and create the PR from the pushed branch.
3. Merging the preparation record triggers **Build Android release** only on `main`. It waits up to 30 minutes for CI on that exact commit, verifies signing, builds/signs the AAB, and saves a draft GitHub Release. Missing/failed/cancelled CI blocks it; rerun CI before retrying. Build reuses CI validation.
4. Build dispatches **Release to closed testing** with its run ID. The shared release queue verifies the successful `main` build and reuses its exact commit/AAB. Install/test that version and check Play Console review/publishing status.
5. Manually run **Publish to production**, confirming testing of the current `main` version. It promotes that tested bundle to full rollout without rebuilding.

No stage takes a version input or falls back to an older release. Finish before merging another bump; retain drafts/tags/assets, and never overwrite successful builds. After build failure, inspect incomplete drafts/tags before manually retrying **Build Android release**. Retry failed **Release to closed testing** from `main`; it resumes the matching successful bundle without a version bump. A newer testing release blocks promotion of its predecessor.

### iOS releases

Release workflows support Android only; unsupported platform inputs fail before preparation writes. iOS development/bundle exports work, but signing, TestFlight, and App Store workflows are not configured.

### GitHub and Play configuration

Under **Repository Settings → Environments**, create these environments with **environment secrets**. Commit names only, never values.

| Environment | Secrets |
| --- | --- |
| `google-play-build` | `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` |
| `google-play-testing` | `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` |
| `google-play-production` | `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` |

- Restrict environments to **Selected branches and tags → branch `main`**; add production reviewers where available and remove repository-level secret copies.
- Set Actions variable `CLOSED_TESTING_TRACK` to the closed-track API identifier (usually `alpha`).
- Keep default token permissions read-only. Enable **Repository Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**, subject to organization policy. Only preparation requests contents/PR/Actions write access to push, create the PR, and dispatch CI; it never approves/merges and needs no extra token secret.
- Enable Google Play Android Developer API. Invite a service account through Play Console **Users and permissions** with app-scoped read, testing-release, and production-release access. Configure track, testers, listing, and policy declarations before submission.
- Back up credentials outside Git; rotate exposed values.

Implementation: [release script](../scripts/release/android.cjs).

For local signing, align generated `android/app/build.gradle` version code with `app.json` or regenerate. Rebuild after changing codes; existing AABs retain their original code.

## Dependencies

Use compatible stable Expo/managed dependencies from manifest/lockfile. Coordinate SDK changes with `pnpm-workspace.yaml` native overrides; explicitly approve preview SDKs/React Native release candidates. Follow regeneration and [native testing](TESTING.md#native-checklist): JavaScript exports do not prove native compatibility.

- Add managed/native packages with `pnpm expo install <package>`; development packages with `pnpm add -D <package>`.
- Commit manifest/lockfile together; check native alignment with `pnpm expo install --check`.
- Upgrade React/test renderer and Vitest/coverage as exact-version pairs. `pnpm deps:check` verifies them within `pnpm verify`.
- Preserve pnpm’s isolated layout; hoist only to resolve an observed issue.
- Run [required gates](TESTING.md#required-gates), including after dependency changes.

[Dependabot configuration](../.github/dependabot.yml) owns schedules, cooldowns, and groups. Review updates before merging; grouping does not establish Expo compatibility. Use Doctor and `expo install --check`.

## Change workflow

Follow [Contributing](../CONTRIBUTING.md) and, for agents, [AGENTS.md](../AGENTS.md). Inspect relevant code/docs, preserve unrelated changes, and follow native checks for UI/persistence work.

Update the owning document instead of appending task logs; link configuration rather than copying versions/thresholds. Report unresolved failures and unperformed checks.

## Documentation privacy

Use repository-relative links and synthetic examples. Never commit credentials, personal paths, private account details, real user exports, or unredacted logs/screenshots. Review artifacts before sharing; a Markdown review does not cover Git history or ignored files.

## Dependency audit exceptions

The audit gate rejects fixable high/critical production advisories. `pnpm-workspace.yaml` records unfixable exceptions for [node-forge RSA signature validation](https://github.com/advisories/GHSA-86w9-cpqp-85rv) and [braces nested-pattern stack exhaustion](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). These are transitive Expo/Metro development/server tooling; the app exposes no corresponding service/signature flow. Exceptions do not prove tooling safety: review on updates and remove when compatible fixes exist.

Inspect `pnpm audit --prod --json` for moderate advisories outside the gate. Do not force incompatible transitive major upgrades merely to suppress reports.
